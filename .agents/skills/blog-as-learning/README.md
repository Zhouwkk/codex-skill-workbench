# Blog as Learning 使用指南

Blog as Learning 是一个把博客写作当作学习过程的 Codex Skill。它不会一开始就替你生成一篇完整文章，而是通过“探 → 学 ↔ 讲 → 写”帮助你暴露认知缺口、补足必要知识、形成自己的解释，再把理解重构成适合读者的文章。

它适合从下面这些起点开始：

- 一个真正想弄懂的问题；
- 一个还没有组织起来的主题；
- 一篇论文或技术报告带来的思考；
- 对一个项目、系统或代码库的拆解；
- 一次论文复现、实验或实现经历。

它不负责博客网站搭建、发布流程、文章 registry、Series 管理或跨对话状态保存。

## 安装

这个 Skill 的源码位于：

```text
.agents/skills/blog-as-learning/
```

在本仓库目录中启动 Codex 时，可以直接发现它。也可以在 Codex 中调用 `$skill-installer`，从下面的 GitHub 目录安装为个人 Skill：

```text
https://github.com/Zhouwkk/codex-skill-workbench/tree/main/.agents/skills/blog-as-learning
```

本仓库只维护 Skill 源码，不会自动把它复制或链接到用户级目录。

## 调用

这个 Skill 只通过显式调用启动。使用 `$blog-as-learning`，并给出一个最小起点即可。

### 从问题开始

```text
$blog-as-learning 我想写一篇博客，弄懂为什么 Attention 要除以 sqrt(d_k)。先帮我探测目前的理解，不要直接给完整答案。
```

### 从主题开始

```text
$blog-as-learning 我想写一篇关于 LLM Agent 的博客，但现在只知道一些零散组件。帮我先建立当前 mental model，找出真正的结构断点。
```

### 从论文或技术报告开始

```text
$blog-as-learning 我想围绕这篇论文写博客。不要按 Motivation、Method、Experiment 做摘要，先帮我确定它真正改变或挑战了我的哪个理解。
```

### 从项目或复现开始

```text
$blog-as-learning 我复现了一个多智能体辩论项目，结果与论文不一致。我想把实现中暴露的隐藏假设写成博客。
```

### 进入写作

当核心理解已经形成后，可以明确要求不同交付物：

```text
基于我们已经形成的理解，先给出一条面向机器学习研究者的文章推理主线。
```

```text
现在请根据我的观点起草完整文章。对仍未确认的地方明确标记，不要替我补造结论。
```

## 使用方式

Skill 默认保持短对话，每轮优先推进一个关键认知节点：

- 缺少必要概念时，它会直接补最小必要知识；
- 已有知识但解释不通时，它会优先引导推理；
- 讲不清关键链条时，会返回定向学习；
- 理解形成后，才根据目标读者进入大纲、正文或审阅；
- 重要技术事实会在学习和公开写作时核实，并区分事实、来源结论、个人解释与假设。

如果最终只是把问题弄懂、决定不发表，也算完成。博客服务于理解，而不是反过来把理解变成发布 KPI。

## 当前边界

v0.1 是 instruction-only Skill，没有脚本、模板资产或持久状态文件。继续同一篇博客时，优先在原对话中调用；如果换了对话，请提供上次留下的核心问题、当前理解、主要卡点和重要不确定性。
